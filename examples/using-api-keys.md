# Using Committee API Keys

This document shows how to use the real, functional API keys generated by the system.

## API Key Format

API keys follow this format:
```
ap_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

- Prefix: `ap_live_` (indicates a live/production key)
- Random bytes: 24 hex characters (cryptographically secure)
- Total length: 32 characters
- Generated using: SHA-256 hashing for secure storage

## Creating an API Key

1. Log in to your Committee dashboard
2. Navigate to **Dashboard → API Keys**
3. Click **Create API Key**
4. Fill in:
   - **Key Name**: A descriptive name (e.g., "Mobile App", "Backend Service")
   - **Product Slug** (optional): Associated product identifier
   - **Rate Limit**: Requests per hour (default: 1000)
5. Click **Create Key**
6. **Important**: Copy the key immediately - it's only shown once!

## Using Your API Key

All API keys are stored as SHA-256 hashes in the database for security. When you use a key, it's hashed again and compared against the stored hash.

### Authentication Header Format

```
Authorization: Bearer ap_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

### Example 1: JavaScript/Node.js

```javascript
const apiKey = 'ap_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx';

// Create a payment link
const response = await fetch('https://pay.iicar.org/api/v1/payment-links', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${apiKey}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    customPath: 'my-product-purchase',
    amountUsd: 29.99,
    description: 'One-time purchase',
  }),
});

const data = await response.json();
console.log('Payment link created:', data);
```

### Example 2: Python

```python
import requests

api_key = 'ap_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx'
headers = {
    'Authorization': f'Bearer {api_key}',
    'Content-Type': 'application/json',
}

payload = {
    'customPath': 'my-product-purchase',
    'amountUsd': 29.99,
    'description': 'One-time purchase',
}

response = requests.post(
    'https://pay.iicar.org/api/v1/payment-links',
    headers=headers,
    json=payload,
)

print(response.json())
```

### Example 3: cURL

```bash
API_KEY="ap_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"

curl -X POST https://pay.iicar.org/api/v1/payment-links \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "customPath": "my-product-purchase",
    "amountUsd": 29.99,
    "description": "One-time purchase"
  }'
```

## API Key Permissions

By default, each API key has these permissions:
- `read:payment_links` - View payment links
- `create:payment_links` - Create new payment links
- `update:payment_links` - Modify payment links
- `delete:payment_links` - Delete payment links
- `read:payments` - View payment transactions
- `webhook:register` - Register webhooks

## API Key Security

### Storage
- Keys are never stored in plain text
- Only SHA-256 hashes are stored in the database
- Original key is only shown once at creation time

### Validation
When you send an API request:
1. Your key is hashed using SHA-256
2. The hash is compared against stored hashes
3. Key metadata is verified (active, not expired, permissions)
4. Request is authenticated or rejected

### Best Practices
1. **Never hardcode keys** - Use environment variables
2. **Rotate keys regularly** - Generate new keys periodically
3. **Use different keys per product** - Enables fine-grained control
4. **Monitor usage** - Check "Last Used" timestamps in dashboard
5. **Disable unused keys** - Toggle `is_active` status
6. **Set appropriate rate limits** - Prevent abuse

## Testing Your API Key

To test if your API key works:

```bash
API_KEY="your_api_key_here"

# Test authentication
curl -X GET https://pay.iicar.org/api/v1/payment-links \
  -H "Authorization: Bearer $API_KEY"
```

If successful, you should receive a 200 status and your payment links list.

## Error Responses

### Invalid Key Format
```json
{
  "error": "Invalid API key format"
}
```
Status: 401

### Missing Authorization Header
```json
{
  "error": "Missing or invalid Authorization header"
}
```
Status: 401

### Expired or Inactive Key
```json
{
  "error": "API key has expired"
}
```
or
```json
{
  "error": "API key is inactive"
}
```
Status: 401

### Insufficient Permissions
```json
{
  "error": "Forbidden"
}
```
Status: 403

## Viewing Your API Keys

In the dashboard:
- **Name**: The key's friendly name
- **Key Preview**: First 8 + last 4 characters (e.g., `ap_live_...xxxx`)
- **Product**: Associated product slug (if set)
- **Last Used**: When the key was last used in an API request
- **Status**: Active or Inactive
- **Rate Limit**: Maximum requests per hour

## Disabling a Key

To stop using a key without deleting it:
1. Go to **Dashboard → API Keys**
2. Find the key in the list
3. Toggle the status to "Inactive"
4. The key will no longer work for API requests
5. Re-enable anytime by toggling back to "Active"
